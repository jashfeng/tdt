# v1.8.0 图层增强 设计文档

> 状态：待用户审阅。所有平台 API 均已完成 context7 验证（验证结论表见下），无同源推断代码。
> 版本：v1.8.0 | 日期：2026-08-16 | 插件：beige-tdt-map

## 1. 目标与范围

为 beige-tdt-map 插件（uni-app x 蒸汽模式天地图 UTS 原生插件）新增 5 项**低风险图层增强**能力，全部向后兼容，不修改任何现有函数行为：

| # | API | 说明 |
|---|---|---|
| 1 | `setStyle(styleJson)` / `removeStyle()` | 运行时替换/还原地图样式（MapLibre Style Spec JSON） |
| 2 | `setMaxBounds(...\|null)` | 参数改 nullable，传 null 清除范围限制 |
| 3 | `addTileLayer(id, url, options?)` | 扩展可选 options（zIndex/opacity/minZoom/maxZoom），默认值与现状一致 |
| 4 | `addWMSTileLayer(id, wmsUrl, layers, options?)` | 叠加 WMS 服务图层 |
| 5 | `isSupportCanvas()` | 平台 canvas 标注能力探测 |

**本轮明确不做**（高风险，单独迭代评估）：折线绘制工具/测距、鹰眼控件、图片覆盖物、富 Marker 自定义图标、原生控件动态管理体系。

## 3. API 设计（interface.uts）

```uts
// ═══ v1.8.0 新增：图层增强 ═══

// 瓦片图层选项（自定义瓦片/WMS 共用；所有字段可选，缺省与现有行为一致）
// zIndex=图层层级（默认追加到最上层）；opacity=透明度 0~1（默认 1 不透明）
// minZoom/maxZoom=图层显示缩放范围（默认 1~18）
export type TileLayerOptions = {
    zIndex?: number
    opacity?: number
    minZoom?: number
    maxZoom?: number
}

// 运行时替换地图样式，参数为 MapLibre Style Spec JSON（version 8）
// - Android/iOS/Web：切换后自动重建此前添加的用户图层（自定义瓦片/WMS/聚合/热力）
// - 鸿蒙：华为 MapKit 样式 schema 与 MapLibre 不兼容，通过 onError 显式上报 code=5（平台不支持）
export declare function setStyle(styleJson: string): void
// 还原天地图默认样式（恢复天地图底图 + 重建用户图层）；从未调用 setStyle 时调用为 no-op
export declare function removeStyle(): void

// setMaxBounds 参数改 nullable：任一参数为 null 即清除范围限制
// （Android 官方 null 清除；iOS 现状一次性限制 no-op；鸿蒙全球范围等效清除；Web setMaxBounds(null)）
export declare function setMaxBounds(minLat: number | null, minLng: number | null, maxLat: number | null, maxLng: number | null): void

// addCustomTileLayer 增加可选 options（向后兼容，不传 options 行为与现状完全一致）
export declare function addCustomTileLayer(id: string, tileUrl: string, options?: TileLayerOptions): void
// 叠加 WMS 服务图层：自动拼装 GetMap 请求（SERVICE=WMS&REQUEST=GetMap&LAYERS=...&
// SRS=EPSG:3857&FORMAT=image/png&TRANSPARENT=true&BBOX={bbox-epsg-3857}&WIDTH=256&HEIGHT=256）
// 移除仍用 removeCustomTileLayer(id)。鸿蒙端显式上报 code=5
export declare function addWMSTileLayer(id: string, wmsUrl: string, layers: string, options?: TileLayerOptions): void

// 当前平台是否支持 canvas 标注（Web=true；Android/iOS/鸿蒙原生=false）
export declare function isSupportCanvas(): boolean
```

`MapErrorDetail.code` 注释扩展：`5=平台不支持`。

## 4. 各端实现方案

### 4.1 图层状态管理（核心防 bug 机制）

MapLibre 三端（Android/iOS/Web）`setStyle` 重建样式后 source/layer 全部丢失，必须**保存状态并在样式加载完成后重建**。重建范围：

| 图层 | Android | iOS | Web |
|---|---|---|---|
| 自定义瓦片层 | 状态扩展存 tileUrl + options，重建 RasterSource/RasterLayer | 同左 | 同左 |
| WMS 层 | 状态存 wmsUrl/layers/options，重建 | 同左 | 同左 |
| 聚合层 | 状态存 points/options，重建（复用现有 addMarkerCluster 内部逻辑） | 同左 | 同左 |
| 热力层 | 状态存 points/options，重建 | 同左 | 同左 |

- Marker/Polyline/Polygon 等 annotation 独立于 style，不受影响，无需处理。
- 各端新增私有函数 `rebuildUserLayersAfterStyle()`，仅被 setStyle 样式回调与 removeStyle 样式回调调用；不触碰现有 API 路径。

### 4.2 各端要点

**Android**
- `setStyle`：`m.setStyle(new Style.Builder().fromJson(styleJson), cb)`，cb 内调用 `rebuildUserLayersAfterStyle()`；解析失败（异常）时 onError(4) 上报且不破坏现状（现有 style 在失败时保持——官方行为：builder 失败地图空白，故需先校验 JSON 含 "version" 字段，校验不过直接 onError 且不执行 setStyle）
- `removeStyle`：`m.setStyle(new Style.Builder().fromJson(buildTiandituStyleJson(currentApiKey, currentMapType)), cb)` + 重建
- `setMaxBounds(null)`：`m.setLatLngBoundsForCameraTarget(null)`（官方确认）
- WMS：拼模板 URL 存 Map，用现有 RasterSource/RasterLayer 机制；`addWMSTileLayer` 内部复用 `addCustomTileLayer` 的实现路径（先拼 URL 再走同一函数），避免双份代码
- 注意：`switchMapType` 现有实现同样会丢图层，但**本轮不改**（超出范围，仅在 README 注明 setStyle/removeStyle 用于需要保留图层的场景）

**iOS**
- `setStyle`：`mapView.styleJSON = styleJson`（官方属性，异步生效）；TDTMapDelegate 增加 `mapView:didFinishLoadingStyle:` 回调，在其中重建天地图底图（`addTiandituTileLayer`，需 state 变量标记当前处于"自定义样式"模式）+ 用户图层
- `removeStyle`：`mapView.styleJSON` 还原为空样式 JSON（与 `getEmptyStyleURL()` 等价的内联空样式）；`customStyleActive` 置回 false，didFinishLoadingStyle 中重建天地图底图 + 用户图层
- 状态新增：`customStyleActive: boolean`（**必要**：iOS 初始加载（initMap 空样式）也会触发 `didFinishLoadingStyle`，无标记会重复叠加天地图底图；仅在 setStyle/removeStyle 触发的加载中执行重建）、用户瓦片层 Map 扩展存 url/options、WMS 状态、聚合/热力状态
- `removeStyle` 与 Android/Web 同为幂等语义（未调 setStyle 时调用 = 重建默认样式，无害）
- `setMaxBounds(null)`：直接 return（现状一次性限制）

**Web**
- `setStyle`：`JSON.parse` 校验（try/catch，失败 onError(4) 不执行）→ `mapInstance.setStyle(styleObj)`，`once('style.load', ...)` 或 `on('load')` 后重建用户图层
- `removeStyle`：`mapInstance.setStyle(默认天地图样式对象)`（与 initMap 构建的默认样式一致）+ 重建
- WMS：`addSource({type:'raster', tiles:[wmsTemplate]})` + raster layer，复用现有 customTileLayers Map
- `setMaxBounds(null)`：`mapInstance.setMaxBounds(null)` 官方支持

**鸿蒙**
- `setStyle` / `addWMSTileLayer`：`onErrorCallback({code: 5, message: "平台不支持...原因"})`，其余逻辑不执行（规则第 7 条：显式上报，禁止静默失败）
- `addTileLayer options`：TileOverlay 有 `setTransparency`/`setFadeIn` 能力 → opacity 用 transparency 映射（opacity=1-transparency）；zIndex 与 min/maxZoom 鸿蒙 TileOverlay 无对应 API → **忽略该选项并在 console.warn 说明**（透明度和现有能力可映射，其余保守忽略，不冒险用未验证 API）
- `setMaxBounds(null)`：`setLatLngBounds(全球范围)` 等效清除（保守方案，见验证表 #9）
- `isSupportCanvas`：false

## 5. 防 Bug 保障机制

1. **context7 前置验证门**：本设计所有平台 API 均已验证（第 2 节表格），实现时注释引用来源；无任何同源推断。
2. **增量追加原则**：新增代码全部追加到各端文件末尾 + 状态变量扩展；唯一签名变更 `setMaxBounds` 改 nullable（传 number 调用零影响，UTS `number | null` 接受 number）。
3. **JSON 前置校验**：setStyle 在 Android/Web 先校验 JSON 可解析且含 `"version"` 字段，校验失败直接 onError，**不执行切换**（避免 MapLibre 解析失败导致地图空白）。
4. **样式加载完成后才重建**：所有重建均挂在官方样式回调中（Android OnStyleLoaded / iOS didFinishLoadingStyle / Web style.load），不在切换途中操作图层。
5. **四层验证关卡**：GetProblems 静态检查 → tdt-web-poc.html 浏览器实测（setStyle 重建断言）→ Android 自定义基座/鸿蒙本地打包编译 → 真机回归清单。
6. **可回滚**：按 Task 粒度 git 提交，任一关卡失败仅回滚该 Task。
